# AGENTS.md — правила разработки ComelyLauncher

Документ для ИИ-агентов и людей, которые продолжают проект. Перед изменениями прочитай `ARCHITECTURE.md`.

## Команды

```bash
npm install            # зависимости; postinstall скачивает бинарник Electron
npm run dev            # Vite dev server + Electron с горячей перезагрузкой UI
npm run typecheck      # проверка типов main и renderer — должна проходить без ошибок
npm run build          # typecheck + компиляция main (tsc) + сборка renderer (vite)
npm run dist           # build + electron-builder + release/ComelyLauncher-Setup.exe (установщик из installer/ с приложением внутри)
```

Перед сдачей любой задачи: `npm run build` без ошибок и предупреждений TypeScript.

## Жёсткие правила

1. **Без комментариев в коде.** Код должен объяснять себя именами функций, переменных и типов. Документация — только в `.md`.
2. **Без заглушек.** Каждая кнопка выполняет реальное действие. Если функцию нельзя сделать честно, её нет в интерфейсе.
3. **Границы слоёв:**
   - `shared/` не импортирует `electron`, `react`, `node:*`.
   - `renderer/` не импортирует ничего из `main/` и не использует Node API; только `api/launcher-api.ts`.
   - `main/` не импортирует ничего из `renderer/`.
   - `main/ipc/*` — только адаптеры: без бизнес-логики, только вызовы сервисов и диалогов.
4. **Контракт IPC — источник истины.** Любой новый канал сначала описывается в `src/shared/ipc/contract.ts`. Домен канала (часть до `:`) должен быть в `IPC_DOMAINS`.
5. **Ошибки — только `LauncherError` с кодом** из `shared/errors.ts`. Для нового кода добавь текст в `errors` в `ru.ts` и `en.ts`. Пользователю ошибки показывает `showError()`.
6. **Все строки интерфейса — через i18n** (`useI18n().t('ключ')`). Ключ добавляется одновременно в `ru.ts` и `en.ts` (тип `Dictionary` не даст забыть).
7. **Размер файлов:** компонент или модуль > ~300 строк — повод разделить. Один файл = одна ответственность.
8. **Без лишних зависимостей.** В `dependencies` только то, что нужно main-процессу во время работы (сейчас `adm-zip`). Всё, что Vite вшивает в renderer (`react`, `react-dom`, `skinview3d`, `@fontsource/*`), лежит в `devDependencies`. Новая зависимость — только если без неё нельзя сделать качественно.
9. **Долгие операции** (загрузки, установки) — через `TaskManager` с шагами, отменой (`signal`) и прогрессом. Не блокировать IPC-вызов дольше нескольких секунд: возвращать `taskId`.
10. **Файлы пишутся атомарно** (`writeJsonFile`, `writeFileAtomic`), пути внутри папки игры собираются только через `GamePaths`.
11. **Безопасность:** токены только в `AccountStore` (шифрование `safeStorage`), никаких токенов в логах и renderer. Внешние ссылки — только `http(s)` через `shell:openExternal`. Пути из архивов проверяются `isInside()`.

## Стиль кода

- TypeScript `strict`, без `any`. Типы домена — в `shared/types/`.
- Имена: классы `PascalCase` (`GameInstaller`), функции и переменные `camelCase` (`resolveVersion`), файлы `kebab-case.ts` в main/shared и `PascalCase.tsx` для React-компонентов.
- Сервисы main — классы с зависимостями в конструкторе, без синглтонов-модулей.
- React: функциональные компоненты, состояние домена — в `state/*-store.ts`, локальное UI-состояние — в `useState`.
- Стили: CSS Modules (`*.module.css`) рядом с компонентом, цвета/радиусы/шрифты — только переменные из `styles/tokens.css`. Акцентные цвета и тёмные поверхности меняются вместе с темой, поэтому прозрачность задаётся через `rgba(var(--accent-rgb), 0.5)` и `rgba(var(--ink-rgb), 0.8)`, а не готовым цветом. Hover-анимации — класс `cl-hover`, появление списков — `cl-stagger`.
- Анимации: общие `@keyframes` объявлены в `styles/animations.css` с префиксом `cl-`. Префикс `cl-` исключён из хеширования CSS Modules в `vite.config.ts`, поэтому на них можно ссылаться из любого модуля. Локальные `@keyframes` модуля называй без этого префикса.
- Иконки — `components/ui/Icon.tsx`; новая иконка добавляется туда как SVG-path в стиле существующих (stroke 2, viewBox 24).
- Ассеты из `/assets` импортируются только через `renderer/assets/catalog.ts`.
- Папки `/assets` и `/screens` — собственность автора и в Git не попадают (см. `LICENSE-ASSETS.md`). Не добавляй их файлы, скриншоты и base64-копии графики в репозиторий. Новый ассет подключай через `catalog.ts`: если файла нет, `scripts/prepare-assets.mjs` создаст однотонную замену, и сборка из открытого кода продолжит работать.

## Чек-лист для типовых задач

**Новая функция в UI, требующая main:**
1. Тип/контракт в `shared/`.
2. Метод в сервисе `main/<домен>/`.
3. Регистрация в `main/ipc/<домен>-ipc.ts`.
4. Стор или вызов `invoke` в renderer, строки в `ru.ts`/`en.ts`.
5. `npm run build`.

**Изменение установки/запуска игры:** проверяй на трёх типах версий — старая (`1.8.9`, `minecraftArguments` + natives), современная (`1.21.x`, `arguments` + rules) и с загрузчиком (Fabric/Forge). Логи лаунчера: `%APPDATA%\ComelyLauncher\logs\launcher.log`.

**Изменение установщика (`installer/`):** код компилируется `csc.exe` из .NET Framework 4, поэтому доступен только C# 5. Для проверки собирай `node scripts/package-exe.mjs --test-build` (нужен `release/app-payload.zip` от electron-builder): такая сборка берёт все пути и ключ реестра из папки `COMELY_INSTALLER_TEST_ROOT` и показывает окна за пределами экрана, чтобы на них нельзя было случайно нажать. Настоящий установщик на рабочей машине для теста не запускай: он закроет запущенный лаунчер.

**Удаление данных:** сборку удаляет только явное подтверждение пользователя (`instances:remove`). Отмена, ошибка или смена папки игры не должны удалять сборку. Незавершённый импорт модпака не виден в списке, потому что `instance.json` пишется последним, поэтому при отмене убирается только его временная папка.

**Нечитаемые данные:** если файл нельзя прочитать, его нельзя молча заменять пустым. Сохрани копию и сообщи пользователю (пример — `AccountStore`).

**Выпуск новой версии:**
1. Увеличь `version` в `package.json`.
2. Выполни `npm run dist`.
3. На GitHub создай релиз с тегом `vX.Y.Z` (та же версия) и приложи файл `release/ComelyLauncher-Setup.exe`. Имя файла менять нельзя: лаунчер ищет именно его. Текст релиза игроки увидят в окне обновления.

Черновики и пред-релизы лаунчер не предлагает. Секреты в репозиторий не добавлять: `SESSION_SECRET` хранится только в Cloudflare.

## Чего не делать

- Не править `screens/` — это референс дизайна автора, а не код приложения.
- Не обходить `IpcRouter` прямыми `ipcMain.handle`.
- Не собирать путь к сборке из её id: папка называется по имени сборки, путь даёт только `InstanceService.dir(id)`.
- Не использовать `backdrop-filter`: он заметно нагружает процессор и видеокарту.
- Не полагаться на то, что окно живо: скрытое окно уничтожается, состояние должно восстанавливаться через `bootstrap`.
- Не хранить состояние в модульных переменных renderer вне `createStore`.
- Не сдвигать строки в прокручиваемых списках через `transform` при наведении: это вызывает появление полосы прокрутки и дёрганье. Подсвечивай фоном.
- Не показывать постоянные панели поверх контента: прогресс задач живёт в боковой панели и раскрывается только по нажатию или при ошибке.
- Не передавать токены входа на сервер поддержки: Microsoft подтверждается сертификатом игрока, Ely.by через `join` и `hasJoined`.
- Не добавлять CurseForge без собственного API-ключа пользователя: без ключа API недоступен.
