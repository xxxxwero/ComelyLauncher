# ComelyLauncher — архитектура

Лаунчер Minecraft Java Edition для Windows на **Electron + TypeScript + React + Vite**.
Приложение разделено на три процесса-слоя и общий слой типов:

```
┌──────────────────────────── renderer (React, Chromium) ────────────────────────────┐
│ screens/  ←  components/  ←  state/ (сторы)  ←  api/launcher-api.ts (invoke/subscribe)│
└──────────────────────────────────────┬──────────────────────────────────────────────┘
                                       │ window.comely (contextBridge)
┌──────────────────────────── preload/index.ts ─────────────────────────────────────┐
│ белый список доменов каналов, один invoke-канал + один канал событий               │
└──────────────────────────────────────┬────────────────────────────────────────────┘
                                       │ ipcMain / webContents.send
┌──────────────────────────── main (Node.js) ────────────────────────────────────────┐
│ ipc/*  →  сервисы домена (accounts, instances, minecraft, content, …)  →  core/*   │
└────────────────────────────────────────────────────────────────────────────────────┘
                 shared/ — типы, контракт IPC, коды ошибок (используют все слои)
```

## Поток вызова (пример: «Играть»)

1. `HomeScreen` → `actions/play.ts → playInstance()` проверяет аккаунт и вызывает `launchGame()` из `state/game-store.ts`.
2. `invoke('game:launch', id, options)` → preload → `IpcRouter` → `ipc/game-ipc.ts` → `GameSessionService.launch()`.
3. Сервис создаёт `GameSession`, запускает `TaskManager`-задачу установки (`GameInstaller`: клиент → загрузчик → библиотеки → ассеты → natives),
   выбирает Java (`JavaService`), получает данные входа (`AccountService.launchCredentials()`), строит аргументы (`launch-arguments.ts`) и запускает `javaw`.
4. Изменения рассылаются событиями `game:session`, `tasks:changed`, `game:log` → сторы renderer → `GameOverlay` перерисовывается.

Все ответы IPC имеют вид `IpcResult<T>`: `{ ok: true, value }` или `{ ok: false, error: { code, message, params } }`.
Renderer превращает ошибку обратно в `LauncherError` и показывает локализованный текст `errors.<code>`.

## Данные на диске

| Что | Где |
| --- | --- |
| Программа (ставит установщик) | `%LOCALAPPDATA%\Programs\ComelyLauncher\` или выбранная папка |
| Настройки | `%APPDATA%\ComelyLauncher\settings.json` |
| Аккаунты (зашифрованы DPAPI) | `%APPDATA%\ComelyLauncher\accounts.dat` |
| Библиотека скинов, свой фон, лог лаунчера | `%APPDATA%\ComelyLauncher\skins`, `backgrounds`, `logs` |
| Папка игры (настраивается) | `%APPDATA%\.comelylauncher` → `versions`, `libraries`, `assets`, `runtime`, `profiles`, `cache` |
| Сборка | `profiles\<имя>\` — обычная папка игры + `.comely\instance.json`, `.comely\content.json` |

## Ключевые решения

- **Один контракт IPC** (`shared/ipc/contract.ts`) — типы аргументов и результатов проверяются и в main, и в renderer.
- **Сервисы без глобального состояния** собираются в `main/app/services.ts` (ручной DI); зависимости передаются через конструктор.
- **Задачи** (`TaskManager`) — единый механизм прогресса для установки игры, контента и модпаков; UI отображает их в `DownloadsDock` и `InstallView`.
- **Версии с наследованием** (`inheritsFrom`) объединяются в `version-resolver.ts`; загрузчики модов создают дочерний `version.json`, поэтому запуск одинаков для всех.
- **Java**: по умолчанию скачиваются официальные рантаймы Mojang нужного компонента (`jre-legacy`, `java-runtime-delta` и т. д.); можно указать свой путь или выбрать найденную JDK.
- **Microsoft**: OAuth в отдельном окне Electron (клиент лаунчера Minecraft) → Xbox Live → XSTS → Minecraft Services; refresh-токен хранится зашифрованным.
- **Ely.by**: Yggdrasil API с поддержкой 2FA, в игру подключается через `authlib-injector`.
- **Локальные изображения** (скриншоты, свой фон) отдаются через протокол `comely-media://` только из разрешённых папок.
- **Загрузки** идут через `node:https` с keep-alive, проверкой SHA-1, повторами и таймаутом простоя.
- **Быстрый запуск игры**: если сборка уже установлена, `GameInstaller.findReady()` проверяет файлы только по размеру и без сети, а полная установка с SHA-1 выполняется лишь при расхождении. JVM запускается с отключённой проверкой байткода (`FAST_STARTUP_JVM_ARGUMENTS`).
- **Старт лаунчера**: окно Electron показывается сразу, а тяжёлый three.js загружается лениво (`LazySkinViewer`). Установщик выдаёт папке программы права `ALL APPLICATION PACKAGES`, без которых падает песочница Electron. Лаунчер работает в одном экземпляре, поэтому перед заменой файлов установщик завершает запущенный лаунчер (`RunningLauncher.cs`). Если запущена игра, установщик ничего не меняет и просит её закрыть.
- **Зависимости модов** (`content/project-installer.ts`) ставятся из трёх источников: `required` в метаданных Modrinth, объявления внутри самого jar (`fabric.mod.json`, `quilt.mod.json`, `mods.toml`, с учётом вложенных jar; `mod-metadata.ts`) и Iris для шейдеров. Идентификатор мода сопоставляется с проектом в `mod-id-lookup.ts`; кандидат из поиска ставится, только если его jar действительно объявляет нужный id.
- **Импорт сборок** (`content/import/`): архив распаковывается потоково через .NET ZipFile в PowerShell, поэтому большие архивы не загружаются в память, а кириллица в именах сохраняется. `package-detector.ts` определяет формат по содержимому, а не по расширению: `modrinth.index.json` — Modrinth, `mmc-pack.json` — Prism/MultiMC (в корне или в одной вложенной папке). Папка Prism копируется, исходная остаётся нетронутой; `logs`, `crash-reports` и подобные временные данные не переносятся. После импорта файлы опознаются на Modrinth по хешу, чтобы у модов были названия и обновления.
- **Профили Modrinth App** (`modrinth-app-profiles.ts`): версия и загрузчик хранятся не в папке профиля, а в `%APPDATA%\ModrinthApp\app.db`. База копируется во временную папку и читается встроенным `node:sqlite`, поэтому запущенному Modrinth App это не мешает и его данные не меняются. Поддержаны текущая схема (`instances` + `instance_content_sets`) и старая (`profiles`). Схема принадлежит чужому приложению и может измениться: при ошибке чтения список просто пуст, а экспорт в `.mrpack` продолжает работать.
- **Язык игры**: при первом запуске `game-options.ts` записывает `lang:` в `options.txt` по языку лаунчера и не меняет выбор, уже сделанный в игре.
- **Папки сборок**: у каждой сборки своя папка `profiles/<имя>`, имя берётся из названия сборки при создании (`instance-folder-name.ts`: недопустимые символы, зарезервированные имена, совпадения). Идентификатор лежит только в `instance.json`, поэтому при переименовании сборки папка не меняется. Соответствие id и папки хранит `InstanceService`; путь к сборке получают только через `instances.dir(id)`. Старые папки `inst-*` и старая папка `instances` переименовываются при запуске.
- **Смена папки игры**: `GameDirectoryMover` переносит только `versions`, `libraries`, `assets`, `runtime`, `cache`, `instances`, а чужие папки рядом не трогает. На одном диске это переименование, между дисками копирование с проверкой свободного места и отменой. Настройки меняются после копирования, исходники удаляются после смены настроек, при ошибке или отмене всё откатывается. Пока идёт перенос, новые задачи не создаются. Папка игры всегда отдельная: любой выбор превращается в `<папка>\ComelyLauncher` (`settings/game-directory.ts`). Исключение только у папки по умолчанию. Если старая настройка указывает на общую папку, при запуске `GameDirectoryMover.migrateLayout` переносит файлы лаунчера в такую подпапку, а чужие папки не трогает. Проводник часто держит открытыми вложенные папки, и Windows не даёт переименовать папку целиком, поэтому в таком случае файлы переносятся по одному (`instances/tree-move.ts`). Опустевшие старые папки удаляются позже, когда их отпустит Проводник, список лежит в `moved-folder-leftovers.json`. Пока перенос не завершён, сборки читаются и из старой папки `instances`.
- **Свои фоны**: `BackgroundLibrary` хранит копии в `userData/backgrounds`, уменьшает их до 2560 px и делает миниатюру. GIF и форматы, которые не читает `nativeImage`, копируются без изменений.
- **Миры**: `WorldService` читает `saves/*/level.dat` через `servers/nbt.ts`. Копии лежат в `<сборка>/backups/<дата>_<папка мира>.zip`, как у ванильной кнопки резервного копирования. Перед восстановлением текущее состояние сохраняется отдельной копией, а замена мира идёт переименованием с откатом.
- **Копия сборки**: `InstanceCopier` копирует папку без `.comely`, `logs`, `crash-reports` и `backups`, переносит индекс контента и создаёт новую сборку с новым id. `instance.json` пишется последним, поэтому незавершённая копия не видна в списке.
- **Экспорт .mrpack**: `MrpackExporter` ищет файлы из `mods`, `resourcepacks` и `shaderpacks` на Modrinth по sha1. Найденные попадают в индекс ссылками, остальные и настройки идут в `overrides/`. Миры, логи и служебные данные не экспортируются. Архивы пишет `core/archive-writer.ts` потоково через .NET.
- **Новости**: `NewsService` читает официальные ленты `launchercontent.mojang.com`, держит результат 30 минут в памяти и хранит последнюю копию в `userData/news.json` на случай отсутствия сети.
- **Подбор памяти**: `shared/memory-recommendation.ts` считает значение по числу файлов контента и объёму RAM, оставляя системе минимум 3 ГБ.
- **Поддержка**: `SupportService` общается с сервером из `support-server/` (Cloudflare Worker и D1). Токены входа на этот сервер не передаются. Microsoft подтверждается подписью сертификата игрока Mojang (`microsoft/player-certificate.ts`), потому что адреса Mojang отвечают серверам Cloudflare ошибкой 403. Ely.by подтверждается через `join` и `hasJoined`. Если подтвердить вход не удалось, игрок всё равно может написать, но без прав админа, а экран поддержки показывает предупреждение и кнопку повтора.
- **Устойчивость к сбоям сети**: параллельные запросы обновления токена объединяются в один (`AccountService.ensureFreshAccount`). Последний удачный профиль скина хранится в `userData/skin-profiles`, а при ошибке загрузка повторяется. Новости берутся из файла, если он моложе 6 часов, а картинки скачиваются по очереди. Логи перед отправкой очищает `sanitizeLog`. Счётчик непрочитанного не обращается к серверу, пока игрок ни разу не открывал поддержку.
- **Цвет интерфейса**: акцент и оттенок поверхностей заданы переменными `--*-rgb` в `styles/tokens.css`. `renderer/theme/accent.ts` вычисляет палитру из одного цвета и записывает её в корневой элемент. Цвет берётся из фона (`resolveAccent`) или из настроек, для своих фонов он определяется в `BackgroundLibrary` по картинке. Цвет считается в main, потому что канвас в renderer не может читать изображения с `file://`, по той же причине цвета обложек заранее записаны в `catalog.ts`.
- **Живой фон**: `ParticleLayer` рисует частицы на канвасе с частотой 30 кадров только на главном экране. Когда окно скрыто, `requestAnimationFrame` останавливается сам, а уничтоженное окно не тратит ничего.
- **Новости разработчика**: сервер поддержки хранит свои новости и список скрытых новостей Mojang. Читать их может кто угодно, писать и удалять только админ. `NewsService` объединяет их с лентами Mojang, кэш новостей разработчика живёт 5 минут.
- **Установщик**: `ComelyLauncher-Setup.exe` собран из `installer/` компилятором `csc.exe` из .NET Framework 4 и содержит архив приложения. Устанавливает только для текущего пользователя, в `%LOCALAPPDATA%\Programs\ComelyLauncher` или в выбранную папку: приложение лежит в `<папка>\app`, рядом `Uninstall.exe`. Новая версия распаковывается в `app.new` и заменяет старую переименованием с откатом. Если в выбранной папке есть чужая папка `app` без файла `.comely-install`, установка отказывается работать. Удаление убирает только программу, ярлыки и запись в реестре, папка с игрой и сборками не затрагивается, а настройки и аккаунты удаляются лишь по галочке. Старая установка из `%LOCALAPPDATA%\ComelyLauncher\app` убирается автоматически.
- **Автообновление**: `UpdateService` раз в 6 часов читает последний релиз репозитория `xxxxwero/ComelyLauncher` на GitHub. Новая версия скачивается в `userData/updates`, проверяется по размеру и sha256 из ответа GitHub и запускается с аргументом `--update`: установщик показывает только прогресс, останавливает лаунчер, заменяет файлы и запускает новую версию. Установщик не подписан сертификатом, поэтому Windows SmartScreen может предупреждать о файле.
- **Экономия ресурсов**: окно, скрытое в трей или на время игры, уничтожается через 20 секунд (`WindowManager.release`) и создаётся заново при показе с `#resume`, без заставки: всё состояние живёт в main и читается через `bootstrap`. `backdrop-filter` не используется, панели просто менее прозрачные. Параллакс по умолчанию выключен и двигает слой напрямую, без React. `SkinViewer3D` рисует только по изменению, непрерывно только при автоповороте. Миниатюры скриншотов отдаёт `comely-media` с параметром `thumb` и кэшем в `userData/thumbnails`.

## Как расширять

| Задача | Что сделать |
| --- | --- |
| Новый IPC-метод | добавить сигнатуру в `IpcContract` → реализовать метод сервиса → зарегистрировать в `main/ipc/<домен>-ipc.ts` → вызвать `invoke()` в renderer |
| Новое событие main → UI | добавить в `IpcEvents`, вызвать `events.emit()`, подписаться в `state/bootstrap.ts` |
| Новый загрузчик модов | реализовать `LoaderInstaller` (`main/minecraft/loaders/loader-types.ts`) и зарегистрировать в `LoaderRegistry`; добавить тип в `LoaderType` |
| Новый способ входа | добавить модуль в `main/accounts/<provider>/`, тип в `AccountType` и `StoredAccount`, ветку в `AccountService` |
| Новый источник контента | клиент рядом с `modrinth-client.ts`, расширить `ContentService.search/install` |
| Новый формат импорта | вернуть `InstancePackage` из своего файла в `content/import/` и добавить проверку в `package-detector.ts` |
| Новый экран | папка в `renderer/screens/<name>/`, маршрут в `RouteId` и `ScreenRouter`, пункт в `Sidebar` |
| Новый язык | файл `renderer/i18n/<code>.ts` с типом `Dictionary`, код в `LanguageCode` и `DICTIONARIES` |
